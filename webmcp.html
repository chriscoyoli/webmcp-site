Agentic web

How this site works with AI agents.

This site now gives AI agents a short menu of things they can do. An agent can look up information and draft a message, and only a person can send it. Here is what that means and how to try it.

Chris Coyoli
November 4, 2026 · Updated November 5, 2026

What this is

An AI agent is software that can carry out a task for you, not only answer questions. You might ask one to "look at this person's recent work and draft them a note." Today, an agent usually has to read a website the way a person would, then guess what to click.

WebMCP is a proposed new web standard, which means browser makers and developers are still working out how it should work. It lets a website give an agent a short menu of things it can do. Each item on the menu is called a tool. It is part of what Chrome calls the agentic web. I added three tools to this site:

  1. See the selected work

    Gives the agent the list of projects shown on the homepage.

  2. Learn about Chris

    Gives the agent the short profile shown on the homepage.

  3. Draft a message

    Fills in a form for the visitor to review. It cannot press Send. On the homepage this is the real contact form. On this page it is a sample.

Why it matters

A clear menu gives an agent a direct way to do a task, so it does not have to guess its way around the page. The site owner also decides what an agent is allowed to do. Here, an agent can do the typing, but the person decides whether to send anything.

WebMCP is still experimental and may change. Regular visitors will not notice anything on this site, because the menu is only for agents in browsers that support it.

How it is built

Chrome's docs describe two ways to give a browser agent structured tools. The imperative API is written in JavaScript. The declarative API adds attributes to an ordinary HTML form. This site uses both.

ToolWhat it doesBuilt withSafeguard
list_portfolioReturns the selected work from the homepage.Imperative APIreadOnlyHint
get_aboutReturns the short profile from the homepage.Imperative APIreadOnlyHint
draft_messageFills in the real contact form on the homepage.Declarative APINo toolautosubmit, so a person presses Send.
draft_inquiryFills in the sample form on this page.Imperative APIChecks its own input. Send is turned off.

The read tools take their answers from the homepage markup, so what an agent reads matches what a visitor sees. An automated browser test also checks tool names, descriptions and output sizes against Chrome's suggested limits.

How to try it

You do not need an AI agent, and you do not need to know how to code. The buttons below do what an agent would do, so you can see the results yourself. You need the Chrome browser on a computer, and it takes about two minutes.

  1. Turn on the feature in Chrome

    Because WebMCP is still experimental, Chrome keeps it switched off. This step turns it on in your own browser only, and it changes nothing on this website. You can set it back to Default at any time.

    • Copy this text into the address bar at the top of Chrome, where you normally type a website, and press Enter: chrome://flags/#enable-webmcp-testing
    • Chrome opens its page of experimental settings. Find the highlighted setting at the top and change its menu from Default to Enabled.
    • Click Relaunch at the bottom of the window. Chrome restarts. Then come back to this page and check the box below.

What the DevTools output means

      
The output is the reply an agent receives after using a tool. It is written in a format software can read:

      

        

          
In the outputWhat it means

          
            
"drafted": trueThe form was filled in.

            
"sent": falseNothing was sent. This is the safety rule working.

            
"filled": [...]The form fields the tool filled in.

            
"keptVisitorText": [...]Fields left alone because the visitor had already typed something different. An empty list means there were none.

            
"next": "..."Tells the agent that the visitor must review the form and press Send.

          
        

      

      
To test the safety check, clear the form and run draft_inquiry again with not-an-email as the email. You should see "drafted": false, a note that the email is not valid, and an empty form.

      
What a successful test proves

      
It shows that a browser can find this site's tools, that the tools return real information, and that the draft tool stops short of sending anything. In these tests, the buttons and DevTools did what an agent would do. It does not show how a particular AI agent would choose or use these tools.

What this does not show

      
These checks test the tools, not how well a real agent chooses and uses them. I have not run WebMCP Evals, Chrome's method for that. This site has also not joined the WebMCP origin trial, so the tools appear only in a browser with the testing setting turned on.
